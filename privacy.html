Data practices

Privacy policy

Last updated: 13 October 2026

This policy describes TelegramHelper, also called Telegram Personal Assistant: a private application operated by its owner for one configured Telegram user. Operator contact: efiboizman@gmail.com.

1. Information accessed

  • Google Calendar: event titles, times, status and identifiers, together with event details returned by the API for listing, matching or changing an event. The current bot uses the connected account's primary calendar. Existing linked reminders retain their original calendar and event identifiers.
  • Google Tasks: task-list and task identifiers, task titles, dates, completion/deletion status and synchronization information. The API can return additional task fields, such as notes, although the current task synchronization does not import notes into local task records.
  • Telegram: user/chat identifiers and incoming text or voice messages needed to process requests and send replies. The configured user's identifier is checked before normal messages and actions are accepted.
  • Authorization: Google OAuth access and refresh tokens and client configuration needed to access the authorized APIs. The bot does not collect the user's Google password.

2. Permissions and purposes

The current application requests https://www.googleapis.com/auth/calendar.events and https://www.googleapis.com/auth/tasks. These allow event management and task management, respectively. No Gmail access is requested, and calendar-list selection is disabled.

Google data is used to display and manage meetings and tasks, maintain synchronization, check event-linked reminders and prepare daily summaries. The operator does not sell Google API data, use it for advertising or use it to train a general-purpose AI model. These purposes are limited to the user-facing personal-assistant features described here.

3. Storage and retention

The application stores task records, reminder descriptions and due times, recurring-reminder settings, Google resource identifiers, synchronization state/history, preferences and pending action details in a server-side SQLite database. OAuth credentials are stored separately on the owner's server with restricted filesystem access.

Deleted tasks and cancelled reminders can remain as marked records, and synchronization history and backups can retain older information. Pending confirmations have a ten-minute validity period; this does not guarantee immediate physical deletion of an expired record. There is no automatic purge schedule for all stored data or backups.

The current code does not itself encrypt the SQLite database or OAuth token cache at rest. Restricted access is not a guarantee of encryption. Diagnostic logs can contain error metadata or provider error details; logs are intended for the operator and are not part of this public site.

4. Service providers and data transfers

  • Google Calendar and Google Tasks: receive authorized API requests to read or change the user's data.
  • Telegram: carries messages, voice recordings, replies, meeting/task summaries and reminders shown to the configured user.
  • Google Gemini API: receives free-text requests for interpretation and voice recordings for transcription. A request can itself include private meeting or task information. The reviewed implementation does not automatically send fetched Calendar/Tasks result lists to Gemini.
  • Oracle Cloud: hosts the application and its server-side records and backups.

Provider handling and retention are governed by the applicable provider terms. Gemini data handling depends on the account and service arrangement, including whether paid or unpaid service terms apply; this policy does not promise that provider processing is excluded from product improvement or human review. See the Gemini API terms, Google privacy policy, Telegram privacy policy and Oracle privacy information.

5. Control, revocation and deletion

The user controls authorization through their Google account. Access can be revoked in Google account connections. Revocation stops future authorized API access but does not automatically erase local records, Telegram messages or backups.

Contact the operator to request removal of local data and retained backups. Bot task deletion or reminder cancellation is not a promise that every historical copy has been erased. The operator must handle any broader cleanup explicitly; it is not performed by this website.

6. This information website

This static website has no login, data-entry forms, analytics scripts or application cookies. It cannot read the bot's database, credentials, calendar or tasks. If hosted on GitHub Pages, GitHub processes website requests, including IP addresses used for security, under its own privacy statement. External links and email services have their own data practices.

7. Changes and contact

This policy must be updated if the application's data practices change. Any new Google data access or purpose must be disclosed before use and, where required, receive renewed consent. Questions can be sent to efiboizman@gmail.com.
